# 前端第二、三轮审查问题修复（2026-10-02）

## 结论

本地完成第二轮 5 类及第三轮新增 2 类问题的修复，共 7 类。新增 36 项前端回归测试和 3 个 Go 顶层回归测试，覆盖真实页面数据流、延迟响应、失败后重试和元数据协议读写。此结论针对已确认问题，不代表全站或生产环境不存在其他缺陷。

审查前的证据见 [第二轮报告](FRONTEND_REVIEW_ROUND2_2026-10-02.md) 和 [第三轮报告](FRONTEND_REVIEW_ROUND3_2026-10-02.md)。这两份报告记录的是修复前行为。

## 改动

| 问题 | 最终实现 | 回归验证 |
| --- | --- | --- |
| 验证码数字跨字段拼接 | 正文存在时不再混入摘要；主题与正文使用内部字段分隔符，正文自身换行仍参与分行数字组合 | 重复数字、截断摘要、真实 MIME 字段、无主题跨行验证码、主题/正文真实冲突 |
| HTML 候选污染与实体乱码 | 移除 head/title/style/script/noscript/template 和注释；使用脱离文档的 textarea 单次解码字符实体，仍以 React 文本节点展示 | 隐藏区块、十进制/十六进制/命名实体、单次解码和真实详情组件 |
| 弹窗旧请求影响新表单 | CreateAliasDialog、AppPasswordDialog、ProxyDialog 与 AccountFormDialog 共用 useDialogSession；同步提交锁，按打开会话和目标隔离结果 | 保存期间输入/取消/Escape/遮罩锁定，A→B→A，旧响应成功/失败，旧完成不能解除新保存锁 |
| 代理检测属于旧输入 | 检测绑定当前会话和 AbortController；改输入、关闭或保存会取消旧检测，旧结果和错误不回写 | 延迟 A 检测期间改 B，B 检测成功后 A 不覆盖结果 |
| 业务标识创建丢草稿 | 创建期间锁定名称、说明和预设；同步 ref 阻止重复提交。同一页令牌创建表单采用相同约束 | 同一事件批次两次提交只发一次请求，输入锁定，失败保留草稿；已有成功创建测试继续通过 |
| 账号编辑重置及重复保存 | AccountsPage 按目标 key 挂载；AccountFormDialog 只在挂载时初始化草稿，父刷新不重置。保存生命周期由会话锁管理 | 真实页面刷新保留草稿、在途 PATCH 始终锁定、卸载后的旧成功不关闭新编辑 |
| 别名说明读写断链 | Go Alias、解析器、前端类型和编辑框完整传递 note；单条/批量成功同步后端缓存及两种前端列表，失败记录保持原值 | 真实 HME HTTP 客户端读写往返、仅改名称保留说明、显式清空、单条/批量部分失败、工作台/全局列表立即重新编辑 |

useDialogSession 在布局 effect 的清理阶段作废旧会话，避免已经提交目标切换但旧异步回调仍持有界面所有权。会话对象的 pending 为同步锁，React busy 只负责界面呈现；关闭、切目标和卸载不会被当作撤回已经发送的服务端写入。

创建或凭据更新成功后，组件始终使实际目标账号缓存失效；只有仍属于当前会话的响应才执行关闭表单等父回调。对应父页面不再重复广播同一次更新。失败时保留用户输入并恢复可重试状态。

验证码字段分隔符只存在于前端嗅探工具内部，不写入 API、正文、日志或界面。普通纯文本输入作为完整字段处理，不把其首个换行误认成邮件主题边界。保留数字长度校验、负向上下文筛选、真正冲突拒绝及 URL 数字隔离。

## 兼容与文档

- Go 别名列表现在真实返回既有 API 文档中的 `note` 字段，包括空字符串；前端允许旧列表缺失该字段并按无说明展示。
- 维护接口原有全字段写入语义不变。省略 note 仍按空字符串处理；只改名称时前端提交已读取的原说明。API.md 补充该契约，避免调用方误以为省略字段会保持原值。
- 明确清空说明仍可用；批量操作只同步实际成功记录的 label/note。现有部分成功、跨批次失败与会话保存警告行为保留。
- 保存中的弹窗现在禁止编辑和取消；代理仅检测期间仍可修改输入，修改会取消旧检测。
- 更新相关目录说明，没有新增依赖、数据库迁移、配置或部署要求。
